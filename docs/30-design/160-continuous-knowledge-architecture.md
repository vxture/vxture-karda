## 1. 三类使用者，同一个知识核心

平台目标：为智能体提供可信上下文，为人提供大幅可探索图谱，并通过 Ontos 的业务语义组织、验证和解释知识。
知识页、图谱、Agent 工具必须是同一授权知识服务的不同投影，不能各建一套事实和证据。
LLM Wiki 的原始来源/知识页/规则三层映射为：

| 层 | Karda 对象 | 真值和责任 |
| --- | --- | --- |
| 来源 | Document、原文 Span、来源版本及 source_ref | 原文不可被模型覆盖；实时业务真值留在 Arda/业务系统 |
| 知识核心 | Entity、Assertion、Evidence、有类型的 Relation、主题定义 | Karda 保存来源陈述、人工确认、冲突和解释；不把 LLM 输出天然视作事实 |
| 规则 | Ontos 的版本化 Schema；Karda 的编译模板、展示配置和审核流程 | Ontos 定业务类型、允许的关系和规则；Karda 定知识编译及消费方式 |
| 消费投影 | 主题页、目录、反向链接、图谱、索引和 Agent KnowledgePackage | 可重建；源版本、权限或人工裁决变化均能失效；Markdown 导出不是权威写库 |

知识服务保留现有 BM25/向量/精排与原文读取；知识抽取独立于嵌入任务，重嵌不抹掉人工确认。
主题页是已发布资产的合成视图；模型先生成草稿，审核后发布，目录、反向链接和引用表由确定性服务维护。

## 2. 语义与身份模型

- SchemaRef = namespace + schemaId + version；消费者必须固定版本，不能静默跟随 latest。
- EntityRef = kbId + entityId。首期只在库内消歧，实体可绑定外部 business_ref；跨库同名不自动合并。
- Relation = stableId + schemaRef + relationType + source EntityRef + target EntityRef + assertionIds + origin。
- origin 三类：asserted（证据支持且经确认的业务边）、inferred（确定性规则推导，附规则版本与前提）、suggested（结构相似性或模型提出的候选）。
- 正式业务图只含 asserted 和经确定性引擎验证的 inferred；suggested 单列审核或探索入口，不成为 Agent 默认事实，不作为支持证据。
- 关系定义用 sourceTypes/targetTypes 约束两端；Schema 只定义类型，实例写在 Karda。本体约束失败应留在待审/失败态，不能偷偷创造类型以求通过。
- 规则推导必须保留 ruleRef、前提关系 ID、规则引擎的确定性输出；模型「推理」文字不等同于规则证明。K1a 只启用 asserted，inferred/suggested 的正式服务入口待后续批次实现。
- 核心资产保留有效时间 validFrom/validUntil，必要时另记 recordedAt。validUntil 采用半开区间；历史读取需独立的授权契约，不开放 caller 任意挑旧版本来绕过现行失效。
- 人工验证到期 verificationExpiresAt 与业务有效期分开；即使后台还未把 verified 转 stale，到期断言也不得进入正式图。持久层映射见 [170](170-semantic-persistence-adapter.md)，as_of 不能冒充 validFrom。

## 3. 编译和变更

1. 接入：来源内容 hash/版本 + 原始字节/规范文本 + source_ref；记录成功、失败、重放、删除/撤回。幂等以库和来源标识、单调版本、编译配置为基础。
2. 分析：Atlas 输出候选资产与逐条原文锚点，不直接改正式资产；原文提示词及执行指令只作为不可信资料处理，不能改变系统规则、发工具调用或扩大权限。
3. 校验：检查类型、对象范围、来源版本及锚点；同一 subject/predicate 的冲突独立进入审核，不能用相似性得分自动裁决。
4. 审核：沿用 KD-209/210/222；文档 verified 不自动验证抽取结果；人确认后机器置信不再影响已确认排序。
5. 发布：同一编译批次在事务/发布版本边界内切换；保存模型和模板版本、输入清单、人工裁决及日志。K1a 的纯读投影不声称实现数据库发布事务。
6. 影响传播：来源 → 证据 → 断言/关系 → 主题页/图索引。撤回一个来源逐断言重新求有效支持集合，不能因为一个主题还剩别的来源就保留主题内所有旧结论。
7. 在线读取先校验权威状态，再返回派生结果。后台清理未完成也不能暴露失效、过期、已被替代或权限撤销后的事实；重建不能复活已撤回来源。
8. 版本事件采用 compare-and-set/单调序号：低版本不得覆盖高版本，同版本重试不能重复发布。断点续跑和故障注入由 K1b 的持久层验收。

对输入规模、展开跳数、返回节点/边数、Atlas 用量设置有界预算；失败输出 partial/degraded 和缺失范围，不能假装完整。
LLM 审核结果不得自动关闭人裁决项。

## 4. 统一读取契约

请求 scope 来自已认证服务端的组织、空间、库可见集与关联交集；caller 只能收窄。
图谱核心不是公开 API；调用方不能把任意用户提供的 visibleKbIds 当作授权结果。
K1a 的传入权威状态是调用方责任，K1b/K2 必须接现有可见集、租户过滤和权威来源读取后方可开放 HTTP/工具面。

| 契约 | 输入 | 输出与约束 |
| --- | --- | --- |
| KnowledgePackage | mode、query/entityIds、服务端 scope、maxTokens | schemaRef、知识版本、对象、断言/有类型关系、来源锚点、缺口/冲突、partial；K1a 不实现模型生成和 token 预算 |
| source_only | query + 已有检索参数 | 只返回原文片段，不混入知识页、模型摘要或规则推导；K2 接实际检索链 |
| graph neighborhood | seeds、relationTypes、maxHops、limits | 仅在已授权、现行、证据有效的业务边上展开；禁止先走私有边再过滤结果；节点和边计数也只来自该范围 |
| evidence | 既有 citation_id、上下文半径 | 延用 get_evidence/get_context 的读取规则，补 sourceVersion、validity；无权限与不存在不能可区分 |
| impact | 管理范围内的 sourceVersionRef | 受影响资产与投影；只对具备治理权限者开放，不能成为跨库存在性探针 |

证据锚点包含 documentId、documentVersion 和原文位置；text 用 start/end 半开偏移，后续图片/表格用 page/region/cell，必须能回到被引用版本。
多来源支持时，只输出当前可见且有效的支持证据；反证和冲突是独立字段，不能充当支持。
权限过滤先于分组、评分、全局聚类、计数及缓存。缓存键至少含身份/授权版本、知识发布版本及 schemaRef。

## 5. 大幅图谱工作台

目标使用独立主画布，布局可恢复，配合可收起证据侧栏；入口有「全局主题」「对象探索」「变更影响」三类。
第一条任务路径：项目 → 条款 → 资质 → 证明材料。节点类型、边语义和状态必须可读，不仅靠颜色编码。

- 全局：对授权后的图聚合成主题和社区；相似性社区帮助导航，不代表本体业务分类。
- 局部：按类型、关系和有效时间展开，限制每次返回量；一跳/多跳查询经过同一知识服务，前端不持有全库隐含图。
- 查证：点击业务边看到支持/反驳、原文位置、源版本、人工确认和有效时间；规则边可看规则版本和前提。
- 对照：新旧版本增删、替代和待审冲突；历史模式标识清楚且单独授权。
- 性能：K3 比较 Canvas/WebGL 与 SVG 的可访问性和维护成本，布局移到 Worker；性能测量固定设备、节点边数、并发及冷热状态。
- 真实状态：loading、empty、partial、degraded、withdrawn；示例图标明 synthetic。键盘能够完成选择、展开和证据读取。

## 6. 先进性的验收

同时测结论正确性、支持充分性、更新/撤回正确性、未授权泄露、冲突识别、人审量、延迟与成本。
K0 先形成可重跑的原文词法基线和开放的样本规范，再加入可公开/脱敏真实材料的独立留出集。合成样本只证明代码行为，不证明真实业务质量。
多跳方案只有同题对照证明收益后默认启用；阈值与负载口径以重构计划 §50 为准。
图数据库、全局 GraphRAG 归纳及自主扩源按负载/质量证据后置决策；不以增加基础设施组件数量衡量先进性。

## 7. 实施边界与迁移

K0 只读盘点和本地基线；K1a 先提供不依赖生产数据库的语义校验和安全图投影；K1b 再落数据库增量、回放队列和现有授权链；K2 接 API/编译和审核。
现行接口兼容，读面默认关闭或未挂路由；生产发布、客户资料迁移和角色变更单独按既有流程。平台 I1 继续暂缓，其他平台对接事项按原交接跟踪。
上游 GPLv3 仅作行为和架构参考，组件如需直接使用需独立核对许可证；本轮不引入任何上游源码/提示词/资产。
