## 1. 为什么现在写这一份

外壳的规则齐了,页面的规则一条没有。现状是**外壳层统一、页面层各写各的**:

> **更正(v0.3)。** v0.1 的这张表里有一条是**错的**:它写着「`description` 有的填有的
> 不填,五个顶层页都没填」。实际上**四个域总览全都填了**。那条观察来自一段只截取
> `PageHead` 前 300 字的临时脚本,而那些调用比 300 字长——**我用一个坏工具的输出当了
> 论据**。逐个读过之后的真实情况在下表,结论(需要页面类型)不变,但**理由换了**:
> 问题不在 `description`,在**两个页面根本没有页头**、以及**没有任何规则说详情页怎么
> 回去**。原表保留在 git 历史里,不在这里粉饰。

| 事实(2026-08-27 逐页核对) | 后果 |
|---|---|
| 每页都是 `PageHead` + 若干 `Card`,四个域总览的 `description` **都填了** | 这一层其实是好的 |
| 但 `/assets/new` 用的是**内联样式的 `<h1>`**,不走 `PageHead`;标题还写着域名「知识资产」而不是这个动作 | 产品里唯一的「新建」入口,读起来像误入了资产总览 |
| `/pipeline/tasks/[id]` 手写了一套「task-flavoured 的 PageHead」,注释自己这么说 | 同一个头部有两套实现,改一处不会同步另一处 |
| 详情页怎么回上一层**没有规则**:`/pipeline/tasks/[id]` 有面包屑,`/assets/[kbId]` 什么都没有 | 从智枢点进一个库,就没有出口 |
| 十三个页面没有类型概念 | 加第十四个时没有可照的样子,只能挑一个像的抄 |

**这不是审美问题。** 没有页面类型,每加一页就要重新决定一次「标题写什么、动作放哪、
返回怎么走」,而每一次重新决定都会和上一次差一点——十三页之后,差的那一点已经足够
让人找不到东西。

## 2. 首页:独立于知识资产(KD-214,已交付;形态见 §2.5,KD-215)

### 2.1 改之前:根路径就是资产域

根路径 `/` **曾经就是**知识资产总览,依据是 owner 的裁定「资产为核,首页即知识资产」,
写在 `(portal)/page.tsx` 的注释里。导航栏第一项「知识资产」指向的也是 `/`。

**所以产品里没有「首页」这个概念**:点品牌名回到的是资产域,而不是一个回答
「整体怎么样」的地方。

### 2.2 那条裁定当时是对的,现在的前提变了

它拍板时,资产域几乎是产品的全部。今天不是:

- **域从一个变成四个**(知识资产 / 供给通道 / 加工管道 / 验证评测),外加常驻的智枢;
- **定位升为 Agent 共享知识基础设施**(KD-017)。一个基础设施的第一屏该回答的是
  **「现在能不能用、供给给谁、质量如何」**,而这三件事**没有一件属于资产域**;
- **产品有了一种「整体不可用」的状态,而没有任何页面会说它。** 没有
  `embedding/default` 端点授权时,加工管线提交不了,**一份文档都进不了可检索状态**
  (见 `60-operations/40-run-atlas-endpoint-grants`)。改之前打开 `/`,看到的是一批
  「有库、没内容」的资产——**看起来像没人上传东西,而不是像系统不可用**。
  **这不是推演:交付时用真库验过**——七份文档、七条驻留在未授权上的任务,首页显示
  「当前不可用 / 模型能力尚未授权,加工管线提交不了」并指出操作单;同一个库在改之前
  只会显示「七份文档、没索引」。

最后一条是决定性的:**一个把「基础设施瘫痪」显示成「你还没开始用」的首屏,是在骗人。**

### 2.3 两条路,与拍板

| | A 维持现状 | **B 建独立首页(已采纳)** |
|---|---|---|
| `/` | 知识资产总览 | 首页 |
| 资产域 | `/`(与首页同址) | `/assets` |
| 导航栏第一项 | 「知识资产」→ `/` | 「首页」→ `/`,「知识资产」→ `/assets` |
| 代价 | 无 | 一次路由迁移;`/` 的既有裁定需 owner 改口 |
| 换来 | —— | 有地方回答「能不能用」;资产域不再兼任两个身份 |

**已拍板 B(owner 2026-08-27)。** 理由不是「大家都有首页」,而是:**「资产为核」说的是产品的重心,不是
首屏的职责**。重心是资产,而第一屏该说的是**这套基础设施此刻的状态**——两者不冲突,
今天把它们压在同一个路由上,才让第二件事没有地方说。

### 2.4 首页必须是什么,以及必须不是什么

首页的内容不能自由发挥,否则它会长成一个没人看的仪表盘。三条约束,均已落地:

**必须回答三个问题,按这个顺序:**

1. **能不能用** —— 检索链是否通(端点授权、加工是否在提交、语料是否非零)。
   不通就把**为什么**和**谁能修**写在第一屏,而不是让人从四个域里推理;
2. **谁在用** —— 供给通道的调用与消费方,即这套基础设施正在服务谁;
3. **可不可信** —— 验证覆盖与评测结论。

**必须不是**:各域数字的拼盘。**一个不能推动任何动作的数字不该出现在首页**——
它属于它自己的域总览,那里有上下文。

**必须给出下一步。** 每一块要么显示「正常」,要么给一个可点的去处(去哪个页、
或者「这条要运维做,单子在这」)。**首页说了问题却不说去哪,只是把焦虑前移。**

### 2.5 三问由什么承载:四张域卡片 + 一条条件出现的条(KD-215,owner 2026-08-28)

§2.4 定的是首页**必须回答什么**,没有定**用什么形状回答**。第一版把三问各摆一块摘要,
再在下面铺四个纯文字入口卡——owner 的评价是「密密麻麻」,而且指出了正确形状:**原来
导航栏那四张域卡片**。改判两条:

**一、三问的承载改为四张域卡片。** 卡片本身就同时回答了「怎么样」和「去哪里」——它有
图、有数、有名字、有二级入口,不需要再在它上面另摆一份摘要。第一版恰恰摆了:通道调用量
既在「谁在用」那一块、又在通道入口卡里,同一个数一屏出现两次。

这**不违反**§2.4 的「必须不是各域数字的拼盘」。那一条禁的是**堆没有动作的数字**;每张
卡片给的是一个域的**一个可动作的读数**加上入口,读数背后的上下文在它自己的域总览里。
判断标准没变:一个数如果不能推动任何动作,它就不该在首页——不论摆成摘要还是摆成卡片。

**二、第一问「能不能用」只在不正常时出现。** 常驻一条绿色的「一切正常」不携带信息:它
每天都在,读的人会学会跳过这个位置,于是它变红的那一天也会被跳过。**只在
`state ≠ ready` 时出现的条,出现本身就是信号。** 加载中也不出——先出一条再收掉会闪一下,
而闪一下的告警比不出更糟,它同样在训练人忽略这个位置。

判断逻辑没有改动,仍在 `kb/home/readiness.ts`;改的只是什么时候把它画出来。

## 3. 页面类型:五类,每类一份契约

现有十三页归入五类。**新增页面必须先归类**——归不进任何一类,说明要么放错了域,
要么这里缺一类,而缺一类要改本文而不是绕过它。

| 类型 | 回答什么 | 现有 |
|---|---|---|
| **首页 home** | 这套基础设施此刻怎么样 | `/`(KD-214 新增) |
| **域总览 domain** | 这个域现在怎么样 | `/assets` `/channels` `/pipeline` `/evaluation` |
| **清单 list** | 这一类东西有哪些 | `/pipeline/tasks` `/evaluation/sets` `/evaluation/queue` `/tools` |
| **详情 detail** | 这一个东西是什么样 | `/assets/[kbId]` `/pipeline/tasks/[id]` |
| **流程 flow** | 做成这件事要几步 | `/assets/new` `/pipeline/rebuild` `/bench` |

### 3.1 每类的头部契约

`PageHead` 已有 `title` / `description` / 关键数 / `actions` 四个位置。契约是
**哪些位置必填**,而不是新增位置:

| 类型 | title | description | 关键数 | actions | 返回 |
|---|---|---|---|---|---|
| 首页 | 品牌 + 定位 | **必填** | 四张域卡片,可用性条按需插在最前(§2.5) | 无 | 无 |
| 域总览 | 域名 | **必填**——这个域负责什么 | 域的健康数 | 域级动作 | 无 |
| 清单 | 清单名 | **必填**——列的是什么、按什么排 | 总数 + 需要注意的数 | 筛选 / 新建 | **必填**,回域总览 |
| 详情 | 对象名 | **必填**——它的身份与归属 | 状态 + 关键属性 | 对象级动作 | **必填**,回来处清单 |
| 流程 | 动作名 | **必填**——做完会发生什么 | 前置条件是否满足 | 只有一个主动作 | **必填**,且是**取消** |

**`description` 五类全部必填。** 四个域总览已经满足;缺的是没有页头的那两页(§3.3)。
**首页是唯一不走 `PageHead` 的一类**——它用 hero 承载同样的三样(标题、一句定位、
关键数),因为第一屏要的是一块面而不是一行头。契约管的是**必须说什么**,不是**用哪个
部件说**;把 hero 也塞进 `PageHead` 只会让那个部件长出一个只有一处用的分支。

`PageHead` 把 `description` 渲染在标题右侧同一行,所以
`PageHead` 把它渲染在标题右侧同一行——**空着的时候标题旁边是一片空白,读者不会知道
那里本来该有解释**。填不出一句话说明这一页的职责本身不清楚。

### 3.2 详情页的返回,不是浏览器后退

**回来处清单**,不是 `history.back()`。详情页可以从清单、从搜索、从智枢、从另一个
详情页的链接进入;后退把人送回上一个**历史**,而返回把人送回这个对象**所属的那一层**。
两者在从智枢点进来时会分岔,而那正是最常见的进入方式。

### 3.3 对齐进度(2026-08-27)

| 页 | 差什么 | 状态 |
|---|---|---|
| `/assets/[kbId]` | 返回指向 `/` | **已改**:指向 `/assets`。KD-214 之前两者同址,**迁路由时这一行没跟着改**,于是「返回知识资产」会把人送到首页 |
| `/assets` 的登录回跳 | 回跳到 `/` | **已改**:回跳到 `/assets`,同一个原因 |
| `/assets/new` | 内联样式 `<h1>`、标题是域名不是动作、无取消 | **未改,而且不该只改头部**:整页用的是 DS 之前的本地样式套件,而且它的注释自称「库清单 + 新建表单」——**它同时还在列库,与 `/assets` 重复**。给它套一个 DS 头部会得到一个头身不一致的页面,而真正的问题是**这一页到底该不该是纯新建流程**。这是 IA 决定,不是对齐 |
| `/pipeline/tasks/[id]` | 手写头部 | 未改——它有面包屑,契约的「返回」是满足的;换成 `PageHead` 是一次纯重构,单独做 |
| `/pipeline/rebuild` | 见 §4.1 | **按钮已禁用并说明原因**;流程本身未建,那是一件功能 |

## 4. 流程页:四段式,而且第二段不能省

流程页是本文唯一规定**内部结构**的类型,因为它是唯一会**改变系统**的类型。

```
① 前置    这件事现在能不能做,不能的话缺什么
② 影响    做下去会发生什么 —— 用真实数字,不是描述
③ 确认    只有读到 ② 才给按钮
④ 结果    做了什么,以及可不可逆
```

**第二段是这一类页存在的理由。** 产品里已经有一个做对了的样板——连接器的撤销预览
(`220-connector-framework`):

> 「你确定吗」问的是一个人回答不了的问题——他不知道按钮背后是什么。预览给出三件事:
> 多少份文档退出检索、**其中多少份是已验证的**、以及该来源标识**已被永久占用**。
> **读不到影响就不给确认按钮**——对未知后果的确认不是确认。

这条现在从「撤销那一页的做法」升为**所有流程页的规则**。

### 4.1 `/pipeline/rebuild` 不是「差一段」,是还没有这条流程

对齐它时发现:那一页的**「发起重建」按钮没有任何 `onClick`**——它不是缺第②段,是
**整条流程都不存在**,页面实际是一块展示「正在重建」的状态板,加一个不会发生任何事的
按钮。

**一个点了没反应的按钮,比没有按钮更糟**:它承诺了一件产品做不到的事,而且要等到有人
真的需要重建时才会发现。已按 §5.1 处理——把它显式禁用并说明原因,而不是留着假装。

把它做成真正的四段式流程需要:重建的触发接口、以及第②段要的**影响预览**(会重建哪些
库、旧索引保留多久、期间检索用什么)。那是一件功能,不是一次对齐,**不在本轮**。

**④ 必须说可不可逆。** 「已开始重建」和「已开始重建,旧索引保留 24 小时」是两句话,
后一句才让人知道自己还有没有退路。

## 5. 操作方式:动作放在哪,由**作用域**决定

四个可放动作的位置,今天靠直觉分配。规则:**动作放在与它作用域相同的层**。

| 位置 | 作用域 | 例 | 不该放什么 |
|---|---|---|---|
| `PageHead` actions | **整页** | 新建库、开始重建 | 只影响一张卡的东西 |
| 卡片头 | **这张卡** | 这个域的扫描、刷新这一块 | 页级动作(会让人以为只影响这张卡) |
| 行内 | **这一行** | 查看、暂停这一条绑定 | 批量动作 |
| **智枢** | **跨页决策** | 待人确认的断言、待处理的异常 | 页面自己的解释性卡片 |

最后一条已经是既有规则(`StewardDock.tsx`:*the cross-page DECISION queue, nothing
else*),这里只是把它和另外三个位置排在一起,好让「该放哪」变成一次查表而不是一次判断。

### 5.1 危险动作的三条

1. **不可逆的动作必须先给影响**(§4 ②)。没有影响可读,就没有确认按钮;
2. **危险动作不与安全动作同色同形**。DS 的 `destructive` 是给它们的,
   「刷新」和「删库」不该长得一样;
3. **成功的回执要说清做了什么**,不是「操作成功」。`Published` 好过 `成功`,
   `已开始重建,旧索引保留 24 小时` 好过 `Published`。

### 5.2 空态是一种状态,不是一张空表

每个清单与域总览都要区分三种空:

| 空的原因 | 该说什么 |
|---|---|
| **还没有** | 怎么创建第一个 |
| **筛掉了** | 当前筛选条件 + 如何清除 |
| **不可用** | **为什么不可用、谁能修** |

第三种是今天缺的那一种,也是 §2.2 那个例子:语料为零时,页面显示的是「还没有」的
样子,而真相是「不可用」。**把不可用显示成还没开始,是这套界面目前最贵的一处失真。**
