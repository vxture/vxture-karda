## 2. 共用计算方式，积分面值不变

沿用平台ADR-014：锚价0.20元/credit，换算目标70%，则校准条件下每credit对应采购成本0.06元。
本轮沿用2026-11-22约13:02 CST Admin回读的采购价，单位元/百万token：

| 路由模型画像 | 输入 | 输出 | 用途建议 |
| --- | ---: | ---: | --- |
| Flash | 2 | 8 | 常规辅助、普通问答、结构化提取 |
| Pro | 9 | 27 | 明确选择的复杂分析、长上下文问答 |
| Embedding | 0.5 | 0 | 文本入库与查询向量 |
| Rerank | 0.8 | 0 | 候选排序，**token计量单位与重复query规则待核实** |

这是登记价，不是本租户实付账单；Flash/Pro为模型画像简称，不推断产品端点当前必定指向该模型。
无cache命中、批量折扣或峰谷折扣假设。未采集成本模型及默认兜底不满足0.06保证。
Rerank页面0.000显示值无法证明真实零费率；以下由采购价反推“校准后的应计点数”，不是宣称当前实际扣点。

`操作采购成本 = Σ(各模型实际输入token×输入采购价 + 输出token×输出采购价)/1,000,000`

`推导点数 = 操作采购成本/0.06`

两个产品相同模型和相同token结构采用同一费率。嵌入、重排、生成各计一次，不额外重复收“问答AI点”。
本地检索CPU不冒充模型token收费。积分已支持micro精度结转，0.13点不是每次强制向上扣1点。
**不通过改面值把300点写成3000点制造权益增加。**套餐点数是购买使用能力，不是等额现金钱包。

下表是可复算场景，不是实际样本、固定扣费表或操作次数保证；输入包括提示词和上下文，输出包括完整响应。

| 操作画像 | 假设工作内容 | 采购成本/次 | 推导点数/次 |
| --- | --- | ---: | ---: |
| Arda轻量辅助 | Flash：输入2000，输出500 token | 0.0080元 | 0.1333 |
| Arda标准SQL辅助 | Flash：输入6000，输出1200 | 0.0216元 | 0.3600 |
| Arda复杂分析 | Pro：输入20000，输出3000 | 0.2610元 | 4.3500 |
| Karda基础文本入库 | 10000 token，嵌入一次 | 0.0050元 | 0.0833 |
| Karda文本入库并提取 | 上述嵌入；Flash输入11000、输出2000 | 0.0430元 | 0.7167 |
| Karda检索，100候选场景 | 查询嵌入+重排，不生成答案 | 0.04906元 | 0.8177 |
| Karda检索，20候选优化场景 | 查询嵌入+重排，不生成答案 | 0.00810元 | 0.1350 |
| Karda标准问答，100候选场景 | 检索后Flash输入6000、输出800 | 0.06746元 | 1.1243 |
| Karda标准问答，20候选优化场景 | 同上生成token，减少重排候选 | 0.02650元 | 0.4417 |
| Karda深度问答 | 100候选检索；Pro输入20000、输出2000 | 0.28306元 | 4.7177 |

检索假设两namespace，各嵌入100-token问题一次。当前VectorRecaller按namespace重新嵌入，
不是整个请求天然只嵌入一次；更多namespace继续放大。优化场景也保留两次，不提前计入未实现的memo收益。
100候选场景假设每候选512 token，再把100-token query每对计入，总61200重排token；
20候选场景按每候选400 token，query同样重复，总10000。供应商可能采用不同单位，必须实账校准。
代码默认poolCap100、单namespace候选最多50；100候选是可达的两namespace场景，不是所有请求固定100。

20候选、更短候选文本属于**未实施的优化方案**。裁剪可能伤害召回与排序，需要固定评测集验证，
不能简单把100改为20就宣布节省且质量不变。普通与深度模式应由用户可理解地选择，不暗中换差模型。
标准问答沿用相同生成token假设，故此处节省仅来自重排，不伪造缩短答案的质量收益。

10000-token原生文本提取例子假设两窗口，各增加500 prompt token，合计输出2000；
代码实际按6000**字符**软窗口且超长段落可超出，不是token硬上限。中文空白分词不能用于证明真实成本。
不是每个文档相同长度，重复导入、版本更新和重建会增加工作量；本例只处理一次，无OCR与重试。
10000 token也不直接对应固定MB或页数，无法按1GiB存储推算导入文档数。

W3中失败要区分：相同请求重放不重复扣；独立重试真实发生的推理仍可能有采购成本，平台补偿政策待明确，
不能向客户保证所有失败天然零成本。先前助手“失败重试不重复扣费”应按此更精确理解。
结构化提取当前后窗口失败会使前窗口重跑；不能因只最后提交一次就认定只花了一次AI。

本轮没有修改平台仓、模型费率、任务实现、套餐草稿或生产配置。发布仍需用户确认，
平台侧需改动时提交详细issue，不在平台仓实施。
