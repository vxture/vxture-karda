## 2. 本阶段交付范围

主题消费不再要求所有者/发布权限：普通data.read用户和有用户身份的Agent，基于调用产品当前挂载/权限，发现已发布关系主题，读取证据汇编和单独人工确认摘要，逐段展开精确原文及来源版本位置。没有已确认摘要时仍能读取当前事实，不自动生成或批准摘要。已撤销裁决、失效来源、未挂载或暂停消费不交付旧正文。

新增karda.topic_knowledge与RP只读API/页面，补的是实际消费功能；不是以新的评测/报告充当功能。真实Agent联调在代码完成后单独留证。

## 3. 后续执行原则

先按上表未齐备的功能实现可验证的完整流程，缺外部契约只阻断对应真实联调；不要重复建设已有功能。性能专项停止，已有容量报告留历史，不把旧机器未达指标当功能缺失。必要的权限、数据正确性和阶段CI仍保留；无理由不做每步全量，功能阶段结束集中验收。

每次汇报：本轮新增/补齐了什么功能、合并上线状态、实际未实现项、外部/业务待验项、下一步；固定17项中的7完成/6进行中/4待门槛（10未闭环）不随子功能自动改变。

## 4. 剩余功能批次（与17项主验收分开）

不能用主验收长期未闭环来掩盖已实现功能，也不能把外部验收写成未开发。当前未齐备的功能归为以下5个交付方向，按完整闭环实施，子项明确标记；不以本机性能作为开发前置条件。

- [x] 已有基础功能：Office/文字层PDF来源与版本证据、编译/审核/发布；Agent知识包/检索/主题/同步；知识页与大画布图谱；维护/审计/工作空间消费控制。扫描PDF OCR预览/确认入库已合并上线v0.12.37，见[发布记录](../50-deployment/390-pdf-ocr-release-20261126.md)。
- [ ] **F1 长资料与复杂来源**：20页以上整份OCR的有界分批识别/进度/恢复及完整确认；尚不支持的复杂编号、公式和复杂视觉。现有OCR并未完成这些子项，真实模型效果另验。
- [ ] **F2 完整知识库权威适配**：tenant/platform/预设库的正式权威与授权契约、撤权/撤回/完整重建。当前同空间user库/OBO消费已实现，外部权威契约只阻断相应适配/联调。
- [ ] **F3 本体规则与解释**：真实Ontos发布版本消费、确定性规则执行、前提证据/解释链、规则版本切换和回滚。当前固定Schema/type校验不冒充规则推理；待真实契约与规则引擎。
- [ ] **F4 外部事件同步**：正式外部消费者订阅、失效事件交付/确认、重试和游标重放。当前主动读取/同步核验及本地审计已实现，外部投递契约和真实消费方待对接。
- [ ] **F5 影子试点与切换工具**：只读新旧结果对照、完整试点运营记录及业务切换流程。现有暂停/恢复/CAS审计不等于完整试点工具；质量裁决/真实Agent/业务试点为独立验收。

主验收固定17项仍7完成、6进行中、4待门槛（10未闭环）；F1–F5只是功能缺项分组，不新增或替换主验收项，不把真实契约未到位记成实现完成。
