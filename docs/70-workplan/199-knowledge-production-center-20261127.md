## 完整流程与验收

创建生产计划→校验/确认→服务端加工与编译→集中候选审核→发布预览→确认逐库发布→服务读取当前知识→追溯/失败恢复。

- [x] 刷新、服务重启和中断后按账本恢复，不依赖页面保持打开。
- [x] 来源/配置变化时旧输入不得继续审核/发布；清楚显示变化原因和重新建计划入口。
- [x] 不同子任务失败隔离，重复操作不重复创建子任务或绕过既有计量幂等；结果不明的外部调用先核对，不盲目重放。
- [x] 集中审核必须显式选中、显示当前证据、说明和数量；不自动认可模型候选或摘要。
- [x] 发布仍逐库原子执行；多库计划可部分成功并逐项显示，不宣称跨库分布式原子发布。恢复历史知识也不是回写历史或恢复失效来源。
- [x] 服务影响只展示当前有权读取的引用关系，不泄漏其他主体配置，也不自动修改服务消费策略。
- [x] 当前身份/空间/产品角色、库管理权/挂载/来源在每个实际动作复核；发布仍单独需要service.publish。
- [x] 新页面/API/持久化/执行器整块贯通；开发只必要定向，阶段末集中CI，正常合并/迁移/上线后按P1–P6逐条汇报。

## 实施对照与阶段边界

- P1：/pipeline/production汇总本人非取消计划的真实步骤；当前库来源分页明确是否匹配当前发布，不冒充全平台/全部任务统计。
- P2：create冻结库配置/语义profile和最多10库/100份/每库32MiB原件；草稿不启动模型，start必填原因与当前修订。
- P3：服务端10秒有界轮转、实例互斥、当前平台名单/订阅/本地角色复核，无持久RP令牌；15分钟租约，旧租约提交拒绝。中断无结果不自动重放，明确核对后选中重试；底层编译三次耗尽需新计划。取消未开始的本计划自有加工任务，保留已开始/共享作业。
- P4：原文证据/指纹CAS断言准入，按库核验期限盖章；冲突候选显式选择，再逐项或最多50项关系裁决。断言审核一事务，关系批量逐项真实结果，不宣称整批原子。
- P5：当前裁决/原件重新核验的逐库发布影响和可管理服务引用；确认排队，实际发布复用既有原子协议，已成功但父收据丢失可按正式事件对账。历史恢复生成新发布，不恢复失效资料。
- P6：冻结来源/配置→实际加工/抽取/编译任务→候选/裁决→发布事件和有权查看服务，实际模型任务ID归因，不伪造费用。失去库管理权时隐藏冻结明细/子任务/发布/服务数据，仅保留本人计划元数据。

已完成3项必要定向、类型及数据/i18n守卫；最终类型、整块CI和生产部署已通过，见下文证据。无本地dev/浏览器/CMD或全量/性能，文件和命令后台执行。独立浏览器点击、真实Atlas/外部Agent/业务质量验收不由受控DB夹具替代。
