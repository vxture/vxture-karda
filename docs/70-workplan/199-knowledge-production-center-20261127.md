## 目标与现状

知识源接入/同步及智能体知识服务中心已交付。现有来源检查、加工/编译任务、候选选择、逐条审核、影响预览/发布和维护诊断已存在，分布于单库审核页和作业中心。本批复用这些后端，补齐来源变化到已发布知识的统一生产编排，形成可恢复、有明确人工审核边界的完整软件流程。不是整理客户语料或另建模型/本体引擎。

## 完整流程与验收

创建生产计划→校验/确认→服务端加工与编译→集中候选审核→发布预览→确认逐库发布→服务读取当前知识→追溯/失败恢复。

- [ ] 刷新、服务重启和中断后按账本恢复，不依赖页面保持打开。
- [ ] 来源/配置变化时旧输入不得继续审核/发布；清楚显示变化原因和重新建计划入口。
- [ ] 不同子任务失败隔离，重复操作不重复创建子任务或绕过既有计量幂等；结果不明的外部调用先核对，不盲目重放。
- [ ] 集中审核必须显式选中、显示当前证据、说明和数量；不自动认可模型候选或摘要。
- [ ] 发布仍逐库原子执行；多库计划可部分成功并逐项显示，不宣称跨库分布式原子发布。恢复历史知识也不是回写历史或恢复失效来源。
- [ ] 服务影响只展示当前有权读取的引用关系，不泄漏其他主体配置，也不自动修改服务消费策略。
- [ ] 当前身份/空间/产品角色、库管理权/挂载/来源在每个实际动作复核；发布仍单独需要service.publish。
- [ ] 新页面/API/持久化/执行器整块贯通；开发只必要定向，阶段末集中CI，正常合并/迁移/上线后按P1–P6逐条汇报。

## 边界

复用已交付来源管理、作业中心、编译配置、模型接入、审核与发布、服务中心。执行计划前说明会触发的真实加工/编译及计量，设置有界执行规模和尝试次数，不伪造可精确预估的金额。实际Atlas能力/授权不足时显示真实阻塞，不假成功。

不依赖未开发Ontos，不扩大机构库/跨空间权威，不修改平台配置或正式客户权限；真实Agent业务质量和切换仍单列。无本地服务/浏览器/CMD窗口，性能不作为功能开发前置。固定17主验收7完成/6进行中/4待门槛保持，I1暂停。

## 实施对照与阶段边界

- P1：/pipeline/production汇总本人非取消计划的真实步骤；当前库来源分页明确是否匹配当前发布，不冒充全平台/全部任务统计。
- P2：create冻结库配置/语义profile和最多10库/100份/每库32MiB原件；草稿不启动模型，start必填原因与当前修订。
- P3：服务端10秒有界轮转、实例互斥、当前平台名单/订阅/本地角色复核，无持久RP令牌；15分钟租约，旧租约提交拒绝。中断无结果不自动重放，明确核对后选中重试；底层编译三次耗尽需新计划。取消未开始的本计划自有加工任务，保留已开始/共享作业。
- P4：原文证据/指纹CAS断言准入，按库核验期限盖章；冲突候选显式选择，再逐项或最多50项关系裁决。断言审核一事务，关系批量逐项真实结果，不宣称整批原子。
- P5：当前裁决/原件重新核验的逐库发布影响和可管理服务引用；确认排队，实际发布复用既有原子协议，已成功但父收据丢失可按正式事件对账。历史恢复生成新发布，不恢复失效资料。
- P6：冻结来源/配置→实际加工/抽取/编译任务→候选/裁决→发布事件和有权查看服务，实际模型任务ID归因，不伪造费用。失去库管理权时隐藏冻结明细/子任务/发布/服务数据，仅保留本人计划元数据。
