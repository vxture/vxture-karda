# 智能体任务上下文组装与交付中心实施计划

日期：2026-11-28。状态：用户已批准C1–C6＋R1/R2整体实施；当前开发中，未验证、未发布。

## 1. 定位与建设目标

Karda负责把可授权、可追溯的知识交付给智能体。Ontos负责通用本体建模、模型仓库与引擎；行业本体定义也不在本批建设范围内。Ontos尚未开发，不以其服务作为本批前置条件，保留现有本地语义配置与Jena能力。

本批完成一个完整板块：用户配置任务知识需求和组装配方，智能体提交任务查询，平台组合当前有权访问的已发布事实、主题、图谱邻域与按策略允许的原文，交付有预算、有证据、有缺口说明的任务上下文包；工作台可查看组装过程和调试结果。

当前服务中心已有facts/topics/source/package四类单项能力、版本发布、预算与调试；knowledge_package已有关系邻域与证据，get_context是引用周边原文。本批复用这些能力，新增任务需求分区、跨能力组装、证据去重、整体预算分配和更新差异，不重建检索引擎、服务发布中心或图数据库。

### C1 具体配置

- 任务名称、说明与有界任务输入；taskId/runId作为调用方声明的追溯元数据，不冒充已校验的外部任务身份。
- 显式知识库范围、实体种子、关系类型和命名需求分区；首期采用结构化配置与查询输入，不自动理解任意业务目标生成执行计划。
- 各分区选择事实/主题/图谱/原文能力、优先级、必需性、验证状态过滤及原文补充策略。
- 复用既有服务管理与不可变版本机制扩展配方引用，避免再造一套服务权限和发布流程。旧四类调用保持兼容。

### C2-C3 组装语义

- 已发布知识优先；原文补充必须显式允许，原文命中不提升为已审核事实。
- 实体由用户明确选择或复用已有身份映射，不跨库自动合并同名实体。
- 查询与有界遍历复用PostgreSQL/Jena及现有读取适配器；不引入第二套图引擎或新向量数据库。
- 证据去重键包含库、来源、版本、哈希及位置，不以文本相似度合并不同版本。
- 有效性仅基于平台已有的来源、发布、审核、冲突和规则状态；不声称自动理解所有行业时效或发现所有语义矛盾。
- 缺口区分无匹配、必需证据不足、来源不可用、规则条件不足、预算排除和后端失败。越权范围整体拒绝，不借缺口信息泄露隐藏资料。
- 下游部分失败只有配方明确允许且不影响必需项时可交付，并标注partial；空结果、部分结果与成功齐备分开。

### C4-C5 交付契约

- 统一返回配方/服务版本、任务需求分区、条目与证据索引、已知冲突、缺口、预算、选择原因、知识修订指纹、组装状态和调用追踪标识。
- 输出JSON为正式结构；可供复制的文本视图由同一结构渲染，保留证据编号。下载前重新核验权限；导出内容无法被平台远程撤回，应提示调用方重核验义务。
- 字节预算为首期硬约束；token不是跨模型通用精确值，不为支持token预算强制调用LLM。
- 固定配方与相同合格候选输入下使用确定性选择和稳定排序；实际知识变化允许结果改变。排除说明不得额外泄露未授权内容。
- 权限校验在调用开始、读取链与输出交付阶段执行；跨阶段修订变化导致混合读取时拒绝并要求重新组装，不能拼接互相冲突的版本。
- 更新依据当前重建结果和旧的受限元数据比较，不保存可绕开权限的历史上下文正文，不新增常驻自动刷新进程。

### C6 页面闭环

入口建议置于知识服务导航下，最终路由在实施设计中确认。

配方列表 → 创建/选择配方 → 配置任务分区及库/实体 → 预览 → 发布 → 调试任务 → 查看分区结果、证据与预算 → 复制接入示例 → 查看调用记录 → 修改版本/停用/回退。

有真实空态、缺口态、部分失败和当前权限变化提示，不放演示统计。普通消费者只使用当前允许的已发布服务；管理者才可修改配方和调试草稿。敏感正文不进入审计日志；已有下游调用沿用计量与幂等约束，不重复计费、不承诺requestId重放旧正文。

## 3. 两项整体收尾

- [ ] R1 阶段集成与发布：整个C1-C6实现后集中执行必要回归、类型/构建/依赖/密钥及真实数据库门禁；按既有PR流程合并，若涉及DDL按既有迁移流程发布，上线后验证版本、健康及权限拒绝。开发中只做必要定向校验，不逐小步全量回归，不安排性能压测，不启动本机命令窗口或本地服务。
- [ ] R2 逐项核对与交接：按C1-C6逐项列出实现文件、页面/API入口、验证证据和限制；同步设计/接口/使用说明/批次状态；明确已实现、已上线、真实外部Agent待联调三个状态。

## 4. 阶段验收场景

1. 管理者建立三分区任务：背景事实、关联实体、原文依据；发布配方后普通消费者通过同一服务获取带引用的上下文。
2. 同一证据被两个分区命中，只保存一份证据，两个分区均可追溯；不同来源版本不误合并。
3. 原文补充关闭时不暗中回退；开启后原文保留来源性质；缺少必需项时状态明确。
4. 收紧预算后可选内容按配置退出，证据和引用完整；必需内容无法容纳时不返回伪完整结果。
5. 撤权、取消挂载、来源变更/撤回、服务停用后无法复用旧正文；刷新差异仅反映当前授权可见的信息。
6. 配方回退不回退访问权；下游失败不被显示成无知识；真实空库页面不编造结果。
7. OBO接口与页面调试结果结构一致，旧四类服务调用兼容；重试/请求标识不重复产生计量副作用。
8. 当前已有规则仅在显式选择且满足现有单库规则边界时参与，推导及前提独立显示，不写入正式事实。

以上是阶段集中验证清单，不要求先建设真实业务语料。采用隔离测试数据验证软件；真实外部Agent联调与业务质量单独留证。

## 5. 本批边界与后续方向

本批不开发Ontos本体编辑器、通用本体模型仓库、行业模型与仿真运行时；不建设数据平台，不引入强制LLM生成，不自动批准/发布知识，不补造平台/机构库授权契约。

后续能力方向：

| 智能体任务上下文组装与交付 | 本次申请，C1-C6加R1/R2整体实施 |
