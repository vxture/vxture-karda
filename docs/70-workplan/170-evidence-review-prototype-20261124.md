# K0 来源证据画布与审阅交互原型

状态：离线交互原型。使用公开开发资料；不构成 K2 知识服务、K3 正式工作台或业务事实发布。
设计依据：[160 持续知识架构](../30-design/160-continuous-knowledge-architecture.md) §5、
[K0 批次](80-knowledge-platform-rebuild-20261124.md)的交互路径验证要求。

## 1. 实际交付

`scripts/knowledge/export-review-graph.ts` 导出无需网络依赖的单文件 HTML。
数据经过既有项目族校验及开发区选择，保留项目在序列化前排除；导出的实际范围为
2 个开发项目、5 份文档、18 个章节、32 道 Agent 草案。图为 25 个节点、23 条包含关系。

大幅 SVG 主画布展示项目 → 文档 → 章节；点击任一层进入侧栏的子文档、章节或精确原文。
可按项目筛选、全文搜索、拖拽平移、缩放与适应画布。节点以形状内文字、类型和颜色共同表达层次。
原始招标公告、更正公告和附件分别保留版本及来源，不把历史原文改写成现行要求。

右侧题目选择器展示草案答案、预期支持章节及该题真实 BM25 Top5 命中情况；
未命中的预期证据同时用虚线及“Top5 未命中”文字标记。点击后仍可打开原始支持章节，
不为了界面观感隐藏漏召回。未知题说明候选不等于可回答。
选中章节展示来源版本、UTF-16 半开位置和对应正文，并可打开原公告/附件。

## 2. 使用和边界

```powershell
node portals/app/node_modules/tsx/dist/cli.mjs scripts/knowledge/export-review-graph.ts D:\new-review-graph\index.html
```

输出仅新建或逐字节一致复现；修改资料或界面后使用新路径。可以直接用浏览器打开 HTML；
本轮额外启动了仅绑定 127.0.0.1 的本地预览，实际文件为工作区外 `knowledge-review-graph-v2-20261124/index.html`。
没有 API、数据库写入或生产路由。后续回执子批支持本页内存保存和 JSON 下载，不向服务端提交。
用户复核仍通过原 24 题包及新增 8 题包或对话逐题回复进行，本轮没有任何已接收的人审结论。

连线只表示资料归属/包含，不是业务关系本体、推理、矛盾裁决或已验证知识。
预期证据来自 Agent 标签；图不会证明标签正确。全部材料仍是有限时点快照，未监测后续更正。
本地结果也不覆盖在线授权、撤回、索引失效、多用户或大规模布局性能。

导出不携带原始 HTML；数据转义脚本闭合符、HTML 元字符及 JS 行分隔符，页面通过 textContent 显示原文。
CSP 只允许与内嵌代码匹配的 SHA256 脚本，没有外部字体、脚本、模型或数据请求。
这是保护本地审阅材料的实现约束，不能替代正式服务端授权。

## 3. 实际验证

- 原始资料导出为 5 文档/18 章节、32 题，未包含保留项目 ID、编号、原始 HTML；重复导出逐字节一致。
- 恶意脚本闭合文本保持为 JSON 数据；校验实际内嵌脚本 hash 与 CSP 一致。
- Playwright 实际浏览：1600×1000 桌面、390×844 窄屏均无横向溢出。
- JUNO 项目过滤后为 12 节点，不含另一项目标签；搜索无匹配时为 0 节点并显示空态。
- h1 的原/新公告证据可定位；更正节展示 UTF-16 [91,272) 与实际正文。
- x11 显示 1/2 支持证据命中，并同时在图和侧栏标记漏召回。
- 节点 Enter 激活后焦点及 aria-pressed 保留，正文显示“自本公告发布之日起5个工作日”。
- 浏览器控制台 0 错误/警告；全量本地测试 981 项，967 通过、14 项隔离数据库测试待 CI、零失败；TypeScript 和五项护栏通过。

截图与浏览快照保存在 git-ignore 的 `output/playwright/`，不把临时浏览工件纳入产品源码。
此批补足 K0 一条资料审阅交互路径，不关闭 K0b，不将 K3a/K3b 标为完成。

## 4. 本地复核回执子批

新导出内嵌当前 32 题的完整指纹绑定复核表，初始均 pending。
在同页核对原文后，可逐题选择认可、修改、拒绝或待复核；明确裁决必须填写复核人和理由，
保存时记录规范 UTC 时间。切换题目保留未保存表单；存在未保存表单时拒绝导出，防止遗漏。
关闭页面前提示内存数据风险，下载只表示已发起，用户须确认 JSON 文件实际保存。
没有自动裁决、批量认可、浏览器持久存储或服务端写入。

导入先检查 JSON 大小、资料/题集/逐题指纹、字段白名单、裁决和归因，再显示计数预览，
必须明确点击应用；已有本页工作时拒绝应用，防止覆盖。错误导入不改变现有裁决。
旧 24 题包和新增 8 题包继续保留；不能直接导入此 32 题版本，也不自动复制旧结论。
浏览器与 CLI 使用同一纯校验器，拒绝自加 acceptedGold 等字段；结构有效不认证复核身份，
不使 acceptedGold 或 humanIdentityVerified 变为 true。合并到金标和正式迁移仍须独立验收。

新入口位于工作区外 `knowledge-review-receipts-20261124/index.html`，本地预览端口 8768；
旧 8767 页面和文件保留。导出 JSON 可通过以下命令检查：

```powershell
node portals/app/node_modules/tsx/dist/cli.mjs scripts/knowledge/project-review.ts check <receipt.json> --history
```

共享校验器的浏览器 VM/服务端一致性测试覆盖版本错配、保留题、重复题、漏字段、
未知字段、空身份/理由、非法日期和超长理由。交互验证只使用明确标为 synthetic 的测试记录，
不计入真实用户复核。本批不关闭 K0b，不更改 K3 或正式服务完成状态。

本批本地全量 982 项：968 通过、14 项数据库隔离测试待 CI、零失败；TypeScript 与五项护栏通过。
真实浏览器验证缺理由拒存、切题保留输入、保存并下载 JSON，CLI 回读为 31 pending / 1 accept，
且 acceptedGold=false、humanIdentityVerified=false；全部仅为 Synthetic UI 测试。
已有工作时导入应用被拒绝；新页面显式应用可恢复回执。

## 5. 完整本地 PDF 的章节与证据画布

后续独立子批把用户提供的完整 PDF 接入同一审阅交互。公开库仅含通用导航、导出器和合成测试；
真实源文件、导航清单、HTML 与 PDF 二进制副本全部留在仓库外。
新增 `export-local-pdf-review.ts` 仅接受单份本地 PDF 和全开发题集，导出前验证原件 SHA256、
规范文本、页码锚点、题集及导航分组，拒绝保留题、改变的原件、仓库内输出和已有目录覆盖。
本批使用 7 个分组覆盖 89 个物理页、28 道待审题，没有重写原题或迁移用户裁决。

导航绑定 PDF 二进制指纹，范围连续覆盖每一页且不能重叠/遗漏；最多 12 个分组。
有章节标题的分组必须在其起始物理页找到同名标题（忽略空白）；封面/目录仅使用明确的页范围标签。
这只是人工整理的资料导航，不推断章节法律效力、语义关系、知识图谱或实体事实。
该标题存在性检查不替代对目录和结构的人工判断，不自动切分扫描图像。

画布按章节分组展开，每窗口最多 12 个物理页，长章节通过前/后窗口继续浏览；搜索检查全部页文本，
匹配结果也分页显示。不把未展开页删除出语料；题目支持按钮会定位到正确章节及分页窗口。
例如同题可以在评分条款和证明模板之间切换，侧栏显示精确页原文与 UTF-16 锚点。
原件链接只指向同目录的 `source.pdf#page=N`，新标签页打开；浏览器 PDF 阅读器实际处理页片段。
没有外部模型、上传或远程资料请求。源 PDF 副本逐字节校验后导出，不将原始本机路径嵌入 HTML。

沿用原 28 题包的 corpus/dataset/case 指纹及回执校验，章节导航调整不会修改草案或金标状态。
同版本旧 JSON 可先预览再明确应用；本页已有工作仍拒绝覆盖。新入口初始全部 pending。
审阅表单在 PDF 模式默认折叠，让证据侧栏先可读；用户展开后逐题保存和导出。
旧 8767/8768 页面保持原样，新资料最终预览使用独立的本机目录 `knowledge-qinbao-canvas-v2-20261124` 和 8770 端口。

```powershell
node portals/app/node_modules/tsx/dist/cli.mjs scripts/knowledge/export-local-pdf-review.ts <source.json> <cases.json> <navigation.json> <source.pdf> <new-outside-directory>
```

合成测试覆盖分组绑定、标题位置、缺页/重叠/乱序/重复 ID、导航不改变回执指纹，
以及真实 CLI 导出的原件/回执一致性、原始路径排除、CSP、改件拒绝与输出保护。
完整开发业务原文未用于 CI 或提交到公开库。本批仍是 K0 审阅路径，不关闭 K0b、K3 或 K2 服务。

本批实际本地验证：990 项测试，976 通过、14 项隔离数据库检查待 CI、零失败；TypeScript 和五项护栏通过。
Playwright 检查 1600×1000 桌面截图、390×844 窄屏无横向溢出；37 页长章节可从 27–38 翻到 39–50；
同题第20页→83页定位切换到正确章节/窗口，原 PDF 链接在新标签指向 source.pdf#page=83。
导入原28题 pending 回执后实际下载 JSON，CLI 回读仍为28 pending、acceptedGold=false。
浏览器控制台零错误/警告。没有填写测试或用户裁决，也没有把图形交互记作业务质量验收。

## 6. 浏览器性能实测与复现

新增 `scripts/knowledge/benchmark-review-browser.js`，通过 Playwright CLI 在独立会话执行。
只接受本机 HTTP 上的全新 PDF 审阅页；检测到已编辑表单或裁决时拒绝运行，避免重新加载丢失工作。
执行会重新加载页面、切换问题和章节，但不填写、保存或导出裁决。必须使用单独的测量会话，不能复用用户审阅会话。

```powershell
npx --yes --package @playwright/cli playwright-cli --session=k0-perf open http://127.0.0.1:8770/
npx --yes --package @playwright/cli playwright-cli --session=k0-perf run-code --filename scripts/knowledge/benchmark-review-browser.js
```

本次测量固定在 PR288 主干版本，89 个物理页、7 个章节分组、28 道开发题；HTML 为 227102 字节。
Windows、i5-10400/12 逻辑核、约 32 GiB 内存、Headless Chromium 157、1600×1000、DPR 1，
同机回环 HTTP、并发 1，无 CPU/网络限速。关闭浏览器 HTTP 缓存，但浏览器进程和操作系统已暖，
因此称为「缓存关闭后的文档重载」，不能称为真正冷启动。

每项保留 30 个原始样本，以 nearest-rank 计算 P95；交互各先暖身 5 次，文档重载没有额外暖身。
交互从实际 Playwright 操作之前的浏览器时间戳计到两次 requestAnimationFrame 回调之后，
包含驱动往返和可操作性等待。两帧仅近似下一次渲染机会，不证明像素已经显示，也不是 INP。
首屏时间从 navigation start 算起，到图节点存在、两次帧回调结束；不使用终端调用的墙钟时间。

| 本次工作负载 | P95 / ms |
| --- | ---: |
| 文档 loadEventEnd | 29.6 |
| 首屏节点就绪及两次帧回调 | 76.3 |
| 全页匹配搜索（89 页，显示首 12 页） | 32.4 |
| 无匹配搜索及空态 | 32.4 |
| 长章节翻到下一页窗口 | 82.4 |
| 切换问题并自动定位首条证据 | 32.4 |
| 点击题目支持证据定位 | 65.9 |

[完整原始样本](180-local-browser-performance-20261124.json)记录时间、环境、工作负载、脚本 SHA256、方法与限制。
FCP 只观测到 29/30 次，报告保留缺失事实，不补齐或用它替代首屏可操作指标。
每次操作另行检查空态、页窗口上限、题目支持页与选中节点和原 PDF 页链接一致；验证不计入该次耗时。
全部操作结束时检查无页面异常、无跨源请求、没有改动裁决或草稿。测量输出不包含业务正文、项目名、题目、原始文件名或本机路径。
另在专用测量会话的复核人字段输入明确的 Synthetic 标记，实际验证脚本在重载前拒绝运行且输入仍保留；
未保存任何裁决，随后关闭该测量会话。原始样本的 P95、最大值和脚本哈希均经独立回算核对。

这些结果补足 K0 的本地浏览器诊断证据；不能验收检索 API 的 700 ms 预算或正式知识图谱的 2 秒预算。
正式服务、网络、并发、授权和撤回、多用户、模型生成、成本与规模分布仍需对应系统验收。
K0b 的人工复核和独立留出仍未满足，P4/K2 的门槛不变；不新增执行项、不增加已完成数量。
