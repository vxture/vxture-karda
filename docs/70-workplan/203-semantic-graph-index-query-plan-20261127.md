# 语义图索引与查询中心实施计划

日期：2026-11-27。状态：**owner 已整体批准三个板块，实施中**。基础：v0.12.51 PostgreSQL + G6 + Jena，见[202](202-graph-foundation-g6-jena-20261127.md)。

## 1. 整板块目标

把当前「每次把已授权窗口交给Jena校验」升级为「持久化、可重建、可运营、版本一致的语义查询底座」，让现有图谱工作台和智能体调用真正共享Jena查询能力。先补查询基础，再完整建设保存视图和图谱叙事；不以新增状态页代替实际查询接线。

技术固定：PostgreSQL权威与运营账本；Apache Jena TDB2持久查询投影、ARQ查询、SHACL校验；G6消费查询结果。无Neo4j。Jena数据目录由单一拥有进程管理，禁止多个临时进程同时打开同一TDB2目录；采用内部常驻Java服务，通过受控产品接口接入，不向用户开放Fuseki/SPARQL。

## 3. 权威与权限设计要求

- 索引存放已发布资产的派生副本，不接收人工直接修改。来源字节、审核、权限仍由PG及原件权威裁决。
- 查询索引必须匹配当前发布/Schema与构建指纹；权限、来源版本、人审、有效期随读取重新核验。命名图仅为分区，不能代替授权。
- 不能全图遍历后过滤；授权有效关系集合必须成为ARQ查询的数据集范围。若仅靠库级分区不能保证，则使用受控数据集视图/授权子图，禁止以结果过滤替代。
- PG与TDB没有跨库ACID。显式管理构建、校验、就绪、失效和切头；权威撤回先阻断消费，再清理图索引。
- 本批实现邻域/多跳查询，不承诺任意最短路径或因果推理；现有窗口路径标明局部范围。后续若需要复杂图算法，优先成熟组件。
- 普通查询不得触发隐式全库重建、模型推理或审批。索引更新不得改变现有事实/审核/发布。

## 4. 迁移策略

1. 当前无数据负担，采用新建空TDB2派生目录和新增PG运营元数据表；不迁移成第二个业务主库。
2. 正常db-init增加元数据表，按baseline/increment/Prisma/98/210同步；不在应用启动时改结构。
3. 分批读取正式发布、生成RDF、SHACL校验、完成索引和清单后切头；未就绪库显示待构建并提供操作，不返回假成功。
4. 没有正式发布的库保持正常空状态，随后首次发布触发构建；不自动导入业务材料、确认候选或伪造事实。
5. TDB2可全部重建；PG和原件备份仍为核心。回退应用至v0.12.51，保留新增表和历史，不执行破坏性down migration。
6. Java常驻进程、持久卷与内部连接由产品部署文件按既有流程交付；不改平台仓、服务器变量或客户权限。

## 5. 验证与完成汇报

开发期间仅必要类型和定向验证。整个G1–G6完成后统一阶段CI：真实TDB重启/恢复、PG迁移、跨版本竞争、权限收缩、来源撤回、图谱/Agent同链查询以及依赖审计。不得每个小批次重复全量，不做旧机器性能专项，不启动本地服务器/浏览器或可见命令窗口；功能与接口集中验证在CI执行，浏览器视觉验收如未执行必须单列。

最终报告逐项标记：实现、阶段验证、合并、迁移、部署、线上探针及未验范围。固定17主验收仍7完成/6进行中/4待门槛，软件子项不自动关闭外部验收；I1暂停。
