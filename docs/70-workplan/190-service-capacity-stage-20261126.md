# 正式知识读取容量阶段

日期：2026-11-26。范围：K3b/K2b可独立完成的容量测量与读取热点优化；不关闭真实业务和全系统规模验收。

## 1. 交付

- 可重复隔离PostgreSQL负载工具：当前DDL初始化、正式编译/裁决夹具/发布/loader/service角色/原件校验，单库100/400、多库4800条关系，1/4路并发和原始样本输出。
- 全目录覆盖、无重复、撤回后旧游标拒绝、当前证据移除、挂载减少后合格数收缩；1000条单发布超预算明确拒绝。
- 正式读取器支持与裁决索引化，同快照已验证裁决绑定复用，保持现有鉴权、来源和损坏拒绝条件。
- 固化owner汇报口径：完成内容、合并/上线、剩余批次、下一步。

## 2. 运行方法

只使用专用本机控制库karda_scale_control，KARDA_SCALE_DATABASE_URL从外部提供；工具创建随机临时库并在结束后删除该精确库。不能使用生产地址或现有业务库。对象为内存合成原件，平台准入回调为已准入，正式本地角色/挂载/发布/来源/审核检查仍实际执行。

从portals/app运行：

```powershell
pnpm exec tsx ../../scripts/knowledge/benchmark-service-capacity.ts <新的报告JSON路径>
```

默认每个场景/并发测10轮，4路场景为40个样本，另记首个观测。nearest-rank P95，包含连接池排队；首次不等于冷缓存。每次新建作者合成UUID，操作系统调度不固定，前后比较只报告观测值。未测网络对象存储、平台网关、HTTP、浏览器首屏、真实Agent或模型耗时，不能当生产SLA。

## 4. 验收与剩余

开发仅2项隔离入口/分位统计定向和类型；实际服务角色容量集中执行，完整回归由阶段CI一次承担，无本地重复全量。CI现有正式发布/loader/来源撤回/裁决变化/损坏拒绝继续覆盖。

固定17项仍7完成/10未完成：进行中K0b、K1b-P5、K2a、K2b、K3b、K5；待门槛K4a、K4b、K6a、K6b。本阶段证明指定合成负载下的实现与延迟，真实资料/系统端到端/业务质量仍需后续验收。

4800关系目录均完整覆盖、无重复；来源撤回拒绝旧游标、后续读取移除证据、挂载减少后可用关系计数4000。1000条单发布拒绝publication_payload_limit，两轮均通过。

**判定：局部优化可交付，规模门槛未通过。** 单库400并发4的facts P95由513.4→270.6ms，4800目录并发4由12950.0→2956.9ms；但4800 facts并发4尾延迟6735.8→9992.7ms，仍存在波动/退化。单请求4800 facts约782.3ms，已经超过原检索预算700ms。不能把单库改善外推为全系统达标，更不能隐去并发长尾；需进一步定位整包复核/完整语料加载、进程调度和GC等耗时，未经剖析不定因。两轮非配对随机交替实验，只作运行观测，不声称统计显著的性能收益。

后续：对4800多库并发进行分阶段耗时剖析，再决定批量SQL、受当前权限/版本绑定的派生索引及更大目录策略；保持完整权威核验，不用缓存跳过来源/裁决检查。浏览器真实首屏/设备/网络及业务规模继续待验。
